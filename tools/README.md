# Tools Catalog

Формат записей: `что это / когда брать / важные входы или артефакты`

- `cargo run -p netstitch-connectors --example discover` / when checking known-app connector discovery on the current machine / prints connector manifests, cross-platform process aliases, discovery sources, and detected executable paths; no secrets, no network, read-only local filesystem plus OS-specific lookup; set `NETSTITCH__CONNECTORS_DIR=resources\connectors\apps` to verify user-editable runtime `.app` connector manifests.
- `cargo test -p netstitch-tool --lib` / when checking the linked native network tool library, endpoint reachability parsing, explicit domain lookup, or cache filling behavior / verifies library ABI/action behavior used by embedded watcher runtime; portable runtime uses native libraries under `libs\`.
- `scripts\package_release_assets.ps1` / when creating a Windows portable zip for local release smoke or GitHub release assets / builds or reuses `dist\NetStitch-win64-portable`, reads `config\version-manifest.json` when `-Version` is omitted, and writes `dist\release-assets\NetStitch-win64-portable-<version>.zip`.
- `scripts/package_release_assets_linux.sh` / when creating a Linux portable tarball for release smoke or GitHub release assets / builds or reuses `dist/NetStitch-linux64-portable`, reads `config/version-manifest.json` when `--version` is omitted, and writes `dist/release-assets/NetStitch-linux64-portable-<version>.tar.gz`.
- `scripts/package_portable_linux.sh --skip-build` / when checking Linux core portable staging after a Linux release build / verifies Linux app/native library layout under `dist/NetStitch-linux64-portable` with `NetStitch`, `NetStitch.desktop`, app icon, `libnetstitch_watcher.so`, `libnetstitch_tool.so`, editable connector apps, language files, and portable storage; integration modules are opt-in via `--package-modules` or `NETSTITCH__PACKAGE_MODULES`, and Linux builds use isolated `target/linux-portable` by default.
- `scripts\wrangler.ps1` / when working on Cloudflare Workers + D1 community cloud sync / runs project-local Wrangler from ignored `.local` without global Node.js; use `scripts\wrangler.ps1 login` for browser auth, `scripts\wrangler.ps1 d1 list` for D1 access checks, and keep Cloudflare API tokens/private keys out of git.
- `scripts\clear_cloud_database.ps1 -Yes` / when an explicit operator request requires wiping NetStitch Cloud D1 before further testing or production use / deletes all client-origin data from `netstitch` D1 (users, client identifiers, sessions, keys, authors, app catalog, observations, OAuth/captcha/rate-limit/audit/cache rows) while preserving schema/migrations and service metadata; omit `-Yes` to require typing `CLEAR netstitch`, add `-Local` only for local D1.
- `scripts\check_cloud_worker.ps1` / when changing the Cloudflare Worker entrypoint / syntax-checks `src\netstitch-cloud-worker\src\worker.js` through project-local Node.js without deployment or network access.
- `.local\tools\sqlite\sqlite3.exe` / when inspecting NetStitch runtime SQLite databases locally without installing global SQLite / project-local SQLite CLI installed from the official Windows x64 SQLite tools archive; verify with `.\.local\tools\sqlite\sqlite3.exe -version`, and use it for read-only diagnostics against `storage\netstitch.sqlite3` or portable `dist\...\storage\netstitch.sqlite3`.
- embedded watcher runtime in `NetStitch.exe` / when checking local monitoring API, browser shell, filesystem routes, or runtime lifecycle / start the desktop app through the documented UI/dev entrypoint; portable runtime uses the in-process watcher and native libraries.
- `scripts/README.md` and `tests/README.md` / when looking for canonical project entrypoints or test batches / scripts catalog contains build/package/runtime commands, while tests catalog starts with the centralized `tests/run.ps1` batch runner.
