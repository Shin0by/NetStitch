# App-коннекторы

Приложение в NetStitch можно добавить вручную по пути к executable, через ярлык Windows или через app-коннектор.

App-коннектор - это редактируемое описание известного приложения: его название, возможные имена процессов, правила поиска на разных ОС и иконка. Благодаря этому NetStitch может найти приложение сам и показывать его под понятным названием, например `Google Chrome`, `Telegram` или `Discord`, а не только по имени файла.

## Что даёт коннектор

- понятное имя приложения в списке;
- набор имён процессов для Windows, Linux и macOS;
- правила поиска установленного приложения на машине;
- единое описание приложения для разных операционных систем;
- отдельные профили для одного executable, если это нужно пользователю;
- переносимую подпись приложения для CSV и облачной публикации.

## Где доступно

- Интерфейс: главное окно -> панель `Отслеживаемые приложения`.
- Ручное добавление без коннектора: в панели `Отслеживаемые приложения` укажите путь к executable, выберите файл через кнопку добавления или выберите Windows-ярлык `.lnk`.
- Пользовательские коннекторы: portable-папка `apps/*.app` рядом с `NetStitch.exe` или Linux-бинарником.
- Иконки коннекторов: portable-папка `apps/icons/`.

Приложение можно добавить и без app-коннектора. Такой ручной вариант подходит для разовой проверки или неизвестной программы: NetStitch будет отслеживать выбранный executable. На Windows можно выбрать ярлык `.lnk`, а NetStitch возьмёт приложение, на которое он указывает. У ручного добавления нет расширенных правил обнаружения и переносимой product-identity, которые даёт коннектор.

## Пользовательские коннекторы

В portable-сборке пользовательские коннекторы лежат в папке `apps/` как редактируемые `.app` файлы. После изменения коннектора перезапустите NetStitch или обновите список приложений.

Portable/installer поставляют набор shipped `.app` файлов, но сами файлы остаются внешними runtime-данными. Если папки `apps/` или нужного `.app` файла нет, NetStitch не создаёт его при запуске и не включает скрытый встроенный список известных приложений; приложение можно добавить вручную по пути.

Минимальный пример:

```toml
id = "my-app"
display_name = "My App"
process_names = ["my-app.exe"]
enabled = true
```

Чаще всего достаточно указать стабильный `id`, `display_name` и имена исполняемых файлов. Для более точного обнаружения можно добавить правила поиска по системным источникам и platform-specific aliases.

Коннектор лучше описывать сразу кроссплатформенно: один продукт может иметь разные имена процессов и способы обнаружения на Windows, Linux и macOS, но в NetStitch он остаётся одним приложением.

## Возможности `.app`

Формат `.app` является внешним контрактом: NetStitch предоставляет общие стратегии поиска, а конкретный файл коннектора описывает, как найти приложение. В код проекта не нужно добавлять отдельную ветку под конкретную программу.

Поддерживаемые discovery rules:

- `app_paths` - Windows `App Paths` lookup по имени executable.
- `known_path` - путь относительно env-переменной, например `LOCALAPPDATA` или `ProgramFiles`; в сегментах пути можно использовать `*`.
- `fixed_path` - прямой абсолютный путь с поддержкой `%ENV%`.
- `root_paths` - поиск относительно набора корней, например `windows_drive_roots` или `windows_drive_games`, с несколькими `relative_paths`. Это удобно для игр и portable-приложений на разных дисках.
- `registry_strings` - чтение строковых значений Windows Registry (`REG_SZ`/`REG_EXPAND_SZ`), где значение может быть прямым путём к executable или папкой установки.
- `store_msix` - поиск Windows Store/MSIX пакетов.
- `macos_bundle` - поиск macOS `.app`.
- `linux_desktop` - поиск Linux `.desktop` и fallback через `PATH`.
- `linux_path` - прямой поиск команд в `PATH`.

Если два коннектора указывают на один executable, NetStitch хранит их как разные приложения по паре `connector id + path`. Это нужно для разных профилей одного launcher-а и для community-коннекторов без правки core-кода.

Полная схема и примеры лежат рядом с shipped manifests: `resources/connectors/apps/README_RU.txt` и `resources/connectors/apps/README_EN.txt`. Эти файлы также попадают в portable-папку `apps/`.
