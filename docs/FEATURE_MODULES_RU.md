# Модули

Модули расширяют NetStitch специализированными сценариями без изменения основного приложения. Модуль может взять подтверждённые данные мониторинга и превратить их в понятное действие: анализ, экспорт, подготовку профиля, загрузку нужных ресурсов или другой пошаговый сценарий.

## Где доступно

- Интерфейс: главное окно -> `Модули`.
- Окна модулей открываются внутри NetStitch и используют тот же стиль desktop и web-интерфейса.
- Файлы portable-модулей находятся рядом с приложением в `integrations/`.

## Что могут поддерживать модули

- выбранные строки мониторинга, домены, диапазоны, порты, протоколы и счётчики обращений;
- предварительный просмотр и анализ перед применением изменений;
- экспортные действия для внешних инструментов или профилей продуктов;
- прогресс, статусы, предупреждения и итоговые отчёты;
- выбранные пользователем папки или файлы, если сценарию нужен локальный путь;
- runtime-подписки на host-события фильтров, monitoring и `Tracked apps`;
- фоновые module-owned задачи, которые запускаются только явным действием пользователя, без autostart при запуске NetStitch;
- стандартные диалоги `OK` и `OK+Cancel` с названием и иконкой модуля;
- поддержку Windows, Linux и macOS, если автор модуля её предусмотрел;
- английский, русский или дополнительные языки интерфейса.

## Как работают интерфейсы модулей

Интерфейсы модулей выглядят как обычные панели, grid-сетки, диалоги, таблицы, кнопки, progress bar и статусы NetStitch. Пользователю не нужно осваивать отдельное приложение для каждого сценария, а web-управление может показывать тот же модульный интерфейс через локально запущенный NetStitch.

Модуль может показывать, какие операционные системы и языки он поддерживает. Если текущая система не поддерживается, NetStitch может показать это явно, а не оставлять пользователя с неработающим действием.

Модульные сообщения попадают в системный лог с source равным имени модуля; события core runtime используют source `core`. `core` и `system` зарезервированы регистронезависимо для id и отображаемого имени модуля, чтобы лог не смешивал host/runtime и module-события. Уровни сообщений фиксированы: `info`, `success`, `warning`, `error`.

Cloud upload/download и CSV import/export остаются только ручными действиями пользователя в основном интерфейсе NetStitch. Модуль может анализировать выбранные локальные строки и сохранять свои результаты в `integrations/<module>/data/`, но не запускает cloud или CSV операции вместо пользователя.

## Для авторов модулей

Модули позволяют автору сосредоточиться на конкретном сценарии, а не заново делать мониторинг, локализацию, выбор строк в таблице, CSV-обмен, progress UI и desktop/web-представление. Хороший модуль может быть небольшим, понятным и полезным, потому что NetStitch уже даёт продуктовую оболочку вокруг него.

Полная документация для разработки модулей находится в [SDK модулей](module-sdk/README_RU.md). Там описаны неизменный C/JSON ABI для native shared library, manifest, UI-сущности, host context, host event subscriptions, разрешённые команды, storage-контур и минимальные примеры на Rust и C++.

Так модули становятся удобным способом делиться специализированными сценариями и при этом сохранять единый интерфейс NetStitch.
