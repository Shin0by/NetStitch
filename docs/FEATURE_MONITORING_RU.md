# Мониторинг и фильтрация

NetStitch показывает сетевые назначения выбранных приложений: IP, домены, порты, протоколы, состояние соединения и количество обращений.

## Что видно в таблице

- приложение, к которому относится строка;
- IP и домен, если домен удалось доказать или импортировать;
- порт, протокол и состояние соединения;
- сетевой диапазон и владелец адреса, если эти данные удалось определить;
- количество обращений и накопленные признаки успешных/неуспешных попыток.

## Домены и диапазоны

NetStitch работает не только с одиночными IP. Если приложение передаёт доменное имя в сетевом соединении, NetStitch может показать доказанный домен рядом с IP. Домены также сохраняются при доверенном CSV-импорте.

Для IP-адресов NetStitch может показывать сведения о сетевом диапазоне и владельце адресного блока. Это помогает понять, относится ли строка к CDN, провайдеру, облачному хостингу или инфраструктуре конкретного сервиса.

Домены и диапазоны не заменяют исходную endpoint-строку. Они дополняют её и помогают фильтровать, подтверждать и готовить данные к дальнейшему экспорту.

## Сетевая диагностика строки

В колонке `Действие` у каждой строки есть кнопка `...` перед кнопкой удаления. Она временно заменяет панель `Мониторинг` панелью сетевой диагностики выбранного endpoint. Верхние панели приложения остаются на месте, а кнопка `Назад` возвращает таблицу мониторинга.

Панель содержит три вкладки:

- `Ping` - проверка достижимости; адрес по умолчанию берётся из IP выбранной строки;
- `Трассировка` - показ маршрута без обратного разрешения каждого промежуточного узла; адрес по умолчанию также берётся из IP строки;
- `DNS lookup` - DNS-запрос для доказанного домена строки или, если домена нет, для её IP.

Цель на каждой вкладке можно изменить вручную. На вкладке DNS дополнительное поле `DNS-сервер` можно оставить пустым, чтобы использовать DNS, настроенный в операционной системе, либо указать IPv4/IPv6 адрес другого сервера. Компактная строка контекста `App / IP / Range / Domain / Endpoint` занимает всю ширину сверху; в каждой колонке лейбл и значение расположены рядом в одном горизонтальном ряду. Ниже панель разделена на две равные половины: вкладки, поля и кнопка запуска находятся слева, поле результата без отдельного лейбла - справа и занимает всю доступную высоту.

Диагностика запускается только явной кнопкой, выполняется в фоне и не изменяет наблюдения, фильтры или подтверждение строк. Строки stdout/stderr появляются в поле результата по мере их получения от системной команды, без ожидания её завершения. Промежуточный вывод хранится только в краткоживущей job-сессии watcher-а, а итог - только в состоянии открытой панели. Desktop и browser UI используют единый локальный start/progress-контракт watcher-а и одинаковые правила полей; ввод и progress polling не вызывают snapshot/render всей рабочей области.

## Расширенный мониторинг

Обычный мониторинг показывает сетевые назначения, которые доступны через системные таблицы соединений. Этого достаточно для многих TCP-сценариев.

Расширенный режим нужен, когда приложению важны сетевые события, которые обычные таблицы ОС показывают неполно:

- UDP и QUIC endpoints;
- быстрые попытки соединения;
- домены из HTTP Host, TLS SNI и QUIC Initial;
- ситуации, когда у приложения есть только локальный UDP socket, но нужно увидеть реальные удалённые адреса.

На Windows расширенный режим может требовать запуск NetStitch с правами администратора и доступные runtime-файлы захвата трафика в portable-папке. Если таких прав или файлов нет, NetStitch продолжает работать в базовом режиме и показывает те данные, которые доступны без расширенного захвата.

## Где доступно

- Интерфейс: главное окно -> панель `Отслеживаемые приложения` для выбора приложений.
- Таблица наблюдений: главное окно -> `Мониторинг`.
- Фильтры: верхняя панель главного окна (`Приложение`, `IP`, `Домен`, `Порт`, `Протокол`, `Статус`, `Публичные`).
- Фильтр `Домен` поддерживает `*` как любое число символов: например, `*example.com` ищет домены с таким окончанием, а `example*.com` - домены с таким началом и окончанием `.com`.
- Footer панели `Мониторинг` показывает сводку `Строк`, `Отображено` и `Выбрано`; общий footer приложения больше не содержит отдельный счётчик строк.
- Switch `Публичные` переключает таблицу между публичными и непубличными IP. Последнее состояние switch сохраняется в SQLite `app_settings` с ключом `ui.monitoring.public_ip`.
- После `Публичные` расположены отделённые вертикальным разделителем switch `Теги` и `Соединение и Счет`. По умолчанию оба включены и отображают соответствующие столбцы в таблице мониторинга. При отключении столбцы визуально скрываются, а освобождённое место получают растягиваемые столбцы. Состояния одинаково применяются в desktop/browser UI и сохраняются в SQLite `app_settings` как `ui.monitoring.show_tags` и `ui.monitoring.show_connection_count`.
- Расширенный режим: верхняя панель главного окна -> `Расшир. монитор.`.
- Локальное хранилище portable-сборки: `storage/`.

Обычный рабочий поток:

1. Выбрать приложение.
2. Дождаться появления строк.
3. Отфильтровать лишнее.
4. Подтвердить строки, которые нужны для дальнейшей работы.

Подтверждение помогает отделить полезный набор данных от шума.

Фильтры мониторинга не удаляют данные из локального хранилища. Они только меняют видимый набор строк, который затем можно подтвердить, экспортировать или использовать в дальнейшей обработке. Во время активного сканирования новые строки сразу проходят через текущие фильтры.

Для desktop и web-интерфейса используется один локальный runtime NetStitch, поэтому выбранные приложения, фильтры и таблица наблюдений остаются единым рабочим состоянием.
