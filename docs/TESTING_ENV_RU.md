# Тестовая среда NetStitch

## Текущее состояние

Основной стек выбран как Rust workspace. Внешние integration modules в текущем репозитории могут иметь собственный module-owned workspace `integrations/<module>/Cargo.toml`, который не входит в core workspace. Базовый verification path строится вокруг `cargo fmt`, backend `cargo check`, regression tests и отдельного `cargo check` для Dioxus UI через project-owned script `scripts/dev_check.ps1`.
Скрипт локальной проверки по умолчанию использует последние 20 логических CPU через process affinity и оставляет первые логические CPU свободными.
`scripts/dev_check.ps1` запускает `scripts/check_secrets.ps1` перед Rust-проверками.
Централизованный запуск тестов выполняется через `tests/run.ps1`: suite `dev` используется в `scripts/dev_check.ps1`, suite `regression` запускает только tracked regression tests, suite `full` запускает расширенный пакет core workspace unit/regression/UI-contract/browser-parity проверок. Module-owned tests запускаются из соответствующего `integrations/<module>/Cargo.toml`.
Команды из `docs/GLOSSARY_RU.md` (`компиль`, `билди`, `деплой` и т.д.) выполняются через `scripts/compile.ps1`: verification, release-сборка workspace и обновление `dist\NetStitch-win64-portable`.
Любое завершение работы Codex по проекту должно перед итоговым ответом пройти `scripts/compile.ps1`, чтобы `dist\NetStitch-win64-portable` всегда содержал актуальную тестируемую версию; если это невозможно, причина и риск указываются явно.
Core portable-папка проверяется через `scripts/package_portable.ps1`; для полной UDP/QUIC проверки рядом должны оказаться WinDivert runtime-файлы. Packaging копирует их из `NETSTITCH__WINDIVERT_DIR` или `NETSTITCH__WINDIVERT_DLL`; если destination-файл уже существует и совпадает по SHA256, он не перезаписывается, чтобы загруженный Windows-драйвер не ломал локальную упаковку. External integration modules не входят в core package по умолчанию; для явной bundled-проверки используется `-PackageModules <id>` или `NETSTITCH__PACKAGE_MODULES`, после чего packaging должен копировать `module.json`, выбранную platform native library из `bin\`, `assets\` и создавать `data\`, не перенося module-owned runtime state в core `storage\`.
Portable packaging должен класть рядом с `NetStitch.exe` native runtime libraries в `libs\`, WinDivert runtime-файлы в корень Windows portable-папки, integration module libraries/assets/data в `integrations\`, `apps\`, `language\` и `storage\`. В GitHub Actions WinDivert берётся из tracked `resources\runtime\windivert\windows-x86_64`, чтобы Windows release zip не зависел от локального окружения разработчика. Runtime-вызовы embedded watcher должны опираться на native tool library из `libs\`; отсутствие enrichment cache не должно ломать UI. Для live monitoring `Domain` заполняется только payload-level источниками `http_host`, `tls_sni` и `quic_sni`, полученными watcher packet sniff path для TCP payload на любых портах и QUIC Initial на UDP/443; packet-domain tests должны покрывать фрагментированный payload, QUIC Initial SNI и задержанный PID/TCP-owner match. CSV import может восстановить домен как доверенное переносимое наблюдение.
Portable packaging должен удалять устаревшие publish-файлы из root `dist\NetStitch-win64-portable`, обновлять shipped `language\en-en.ini`/`language\ru-ru.ini` без удаления пользовательских `.ini` локалей, обновлять shipped connector `.app` manifests и `.svg` иконки в `apps\`/`apps\icons`, не удаляя пользовательские `.app`, `.svg` и `.png` иконки; `storage\` остаётся только runtime state. При каждой Windows/Linux portable-сборке packaging ставит marker `storage\clear-system-events-on-next-start`; первый запуск после сборки очищает только `system_events`, чтобы тесты не смешивали свежие сообщения со старой историей, но не удаляет observations, tracked apps, настройки или cloud session.

## Инструменты разработки

На новом рабочем месте сначала установить и проверить:

- Git for Windows / нужен для checkout, SSH/HTTPS push и работы GitHub Actions history / проверка: `git --version` и `git remote -v` в корне проекта.
- GitHub CLI `gh` / нужен для просмотра GitHub Actions runs, релизов, артефактов и диагностики deploy без браузерных догадок / установка Windows: `winget install --id GitHub.cli -e --source winget`, fallback: `choco install gh -y`; авторизация: `gh auth login`; проверка: `gh auth status`, `gh run list --repo Shin0by/NetStitch --limit 10`, `gh workflow list --repo Shin0by/NetStitch --all`.
- PowerShell 7 / нужен для canonical scripts и стабильной Unicode/JSON обработки / проверка: `pwsh --version`; Windows PowerShell допустим для простых команд, но release/tooling scripts предпочтительно запускать в PowerShell 7.
- Rust stable toolchain / нужен для core workspace, native libraries и regression tests / установка через `rustup`; проверка: `rustc --version`, `cargo --version`, `cargo test -p netstitch-regression --test package_app_docs`.
- Node.js LTS / нужен для Cloudflare Worker tooling и web-related scripts, если затрагивается cloud contour / проверка: `node --version`, `npm --version`; project-local Wrangler запускается через `scripts\wrangler.ps1`.
- Cloudflare local env / нужен для live Worker/D1 checks и deploy с новой машины / создать ignored `.env.cloudflare.local`, заполнить `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`, `NETSTITCH_GOOGLE_CLIENT_ID`, `NETSTITCH_GOOGLE_CLIENT_SECRET`, `NETSTITCH_GOOGLE_REDIRECT_URI`, `NETSTITCH_IDENTITY_PEPPER`, затем в одной PowerShell-сессии выполнить `scripts\load_cloudflare_env.ps1; scripts\check_cloud_config.ps1`. Значения не коммитить; для GitHub Actions использовать secrets/variables с теми же provider/project namespaces.
- Cloud D1 cleanup tooling / проверять после изменений operator-очистки и перед ручным live cleanup / `scripts\clear_cloud_database.ps1 -Scope AppData -Yes` очищает только app catalog/observations/domain verification rows, а `-Scope All -Yes` выполняет полный reset; live запуск требует предварительно загрузить ignored Cloudflare env и не должен выполняться из тестов без явной operator-команды.
- WSL `NetStitch-Linux-Test` / нужен для Linux portable/installable build/smoke и памяти в итоговом push-блоке / проверка: `wsl -l -v`, `wsl -d NetStitch-Linux-Test -- uname -a`, `wsl -d NetStitch-Linux-Test -- bash -lc "cd /mnt/c/Programming/GitHub/Netstitch && ./scripts/wsl_memory_status.sh"`; Linux UI testing должен ставить локально собранный `.deb` из `scripts/package_linux_deb.sh`, чтобы проверить зависимости, `/usr/bin/netstitch` и desktop launcher.
- SQLite CLI / уже установлен в project-local ignored contour `.local\tools\sqlite\sqlite3.exe`, чтобы диагностировать runtime SQLite без системной установки / проверка: `.\.local\tools\sqlite\sqlite3.exe -version`; если `.local` отсутствует на новой машине, скачать официальный Windows x64 `sqlite-tools` архив с `sqlite.org/download.html` и распаковать `sqlite3.exe` в тот же путь.
- WinDivert runtime / нужен для Windows UDP/QUIC monitoring и portable packaging / передавать через `NETSTITCH__WINDIVERT_DIR`, `NETSTITCH__WINDIVERT_DLL` или `scripts\compile.ps1 -WinDivertDir <path>`; проверять наличие `WinDivert.dll` и `WinDivert64.sys` в Windows portable-папке.
- Browser для web UI smoke / нужен для проверки embedded web server и локального web-access flow / URL берётся из footer desktop-приложения; smoke можно запускать через `tests\web_access_smoke.ps1`, когда затрагивается web access.

## Ожидания к тестовому контуру

- Все полезные regression tests должны храниться в `tests/`.
- Каждый test entrypoint должен быть описан в `tests/README.md`.
- Для каждой затронутой области перед commit/push должен быть пройден минимально достаточный verification path.
- Module SDK/API изменения должны иметь regression-проверку route/payload/host-command whitelist, `browse_window` desktop/browser picker parity, live `ui_values` event polling для долгих `ui_action` без legacy-маппинга `download_progress`, desktop/browser parity для UI-сущностей, layout defaults, footer/back-контракта и документацию в `docs/module-sdk/`.
- Module SDK example изменения должны обновлять оба showcase-примера (`ui-entity-showcase-rust` и `ui-entity-showcase-cpp`), готовые архивы в `docs/module-sdk/packages/` и локально установленные Windows showcase-модули через `scripts/install_module_sdk_examples_to_portable.ps1`; Linux-архивы собираются только в отдельном тестовом WSL `NetStitch-Linux-Test`, не в других пользовательских WSL.
- Storage boundary regression для внешних модулей проверяется unit tests: core SQLite schema allowlist не допускает module/integration runtime tables/settings, integration host отдаёт модулю `integrations/<module>/data`, а module-runtime tests проверяют создание `integrations/<module>/data/module.sqlite3`; пакет `full` в `tests/run.ps1` включает core/host проверки, а module-owned tests запускаются в контуре конкретного модуля.
- Перед первым push на новой машине нужно прогнать `scripts/setup_github_push.ps1 -TestGitHub`; если SSH на `github.com:22` недоступен, повторить с `-UseHttpsPort443`. После генерации нового ключа проверить, что в GitHub Deploy keys добавлен именно public key из `~/.ssh/netstitch_github_deploy.pub`.

## Локальные ограничения

- Не использовать временные одноразовые diagnostics как substitute для tracked tests.
- Не хранить локальные secret configs внутри tracked test fixtures.
- При появлении внешних интеграций фиксировать offline и mock-friendly режимы.
- UDP/QUIC проверка на Windows требует локального WinDivert runtime и запуска `NetStitch.exe` с правами администратора; без этого Windows backend корректно деградирует до TCP owner tables. Linux basic backend проверяется отдельно через `/proc/net` и не покрывает WinDivert UDP/QUIC path.
- Embedded watcher runtime проверяется через desktop/browser UI и unit/regression tests: cold-start не блокирует первый paint, start/stop monitoring выполняются через app-owned actions, shutdown освобождает `NetStitch.exe` и native libraries.
- IP/domain/network tool проверяется отдельно от UI как native library ABI: library отвечает на `health`, `once`, `lookup`, `lookup-domain` и `probe-endpoint`; `once` не блокирует embedded watcher/UI path при DNS/WHOIS ошибке, `lookup-domain` резолвит A/AAAA адреса и возвращает список `resolved_ips` плюс enrichment-сводки, а `probe-endpoint <[protocol://]host:port...>` требует caller-provided targets, поддерживает IPv4, bracketed IPv6 и домены, не имеет встроенного списка адресов; дополнительные имена команд в pre-release контуре не поддерживаются; unit tests проверяют verified-domain parsers (`HTTP Host`, TCP `TLS SNI`, QUIC Initial SNI), WHOIS parser, native ABI health, parsing domain lookup, protocol-aware endpoint probe parsing и DNS UDP probe без сети.
- Headless/automation workflow не имеет canonical portable smoke до появления нового documented app-owned entrypoint; regression coverage должна проверять native-only portable package и UI lifecycle.
- Connector discovery тестируется unit tests helper-логики, включая разбор Windows App Paths registry values, строковые значения реестра, root-path discovery по корням дисков/папкам Games, Store/MSIX package folder discovery, macOS `.app` bundle discovery и Linux `.desktop` Exec/TryExec parsing без зависимости от конкретной машины; живую проверку текущей машины выполнять через `cargo run -p netstitch-connectors --example discover`.
- Runtime connector manifests тестируются unit tests parser-а и ручной проверкой `NETSTITCH__CONNECTORS_DIR=resources\connectors\apps cargo run -p netstitch-connectors --example discover`.
- UI tests и diagnostics должны опираться на стабильные UI-сущности (`id`, `data-ui-entity`, `data-ui-action`, `data-ui-key`), а не на локализуемые строки интерфейса.
- UI tests для окна `Информация` должны проверять update-check contract без реального GitHub-запроса: сравнение version/revision, наличие зелёного класса header-кнопки только при более высокой версии, наличие stable id/action у кнопки `Обновить программу` и то, что кнопка открывает браузер через общий opener вместо автоустановки.
- UI style tests должны считать `Tracked apps` эталонной panel/control/list-row сущностью: базовые `.card`, `.card__header`, `.input-box`, `.button`, `.switch` и list-row правила должны наследовать её compact spacing, `3px` radius, плоскую palette и stable selectors. Все panel headers в desktop и browser должны повторять высоту, padding, размер шрифта и `title-with-help` структуру `Tracked apps`; глобальные пояснения панели должны быть только в круглой tooltip-иконке `?`, а не отдельным видимым текстовым абзацем. Badge/chip/pill surface в пользовательском интерфейсе запрещены для статусов и счётчиков: header-статусы используют `panel-header-meta`, верхние показатели используют `header-label`, table/status значения используют `state-label`, без фона/рамки/pill-геометрии.
- UI style tests должны проверять общий `value-label` контракт для лейблов слева от значений: desktop и browser используют одинаковый размер, цвет, вес и line-height как у `Ignored addresses`, включая module-provided строки в модульных overlay.
- UI tooltip smoke должен проверять каждую новую tooltip-сущность как desktop/browser contract: tooltip рендерится через стабильный `data-tooltip` и общий floating tooltip-layer, имеет единый стиль в desktop и browser, появляется рядом с контролом, не дублируется native `title`, не ограничивается `overflow` родительских card/list/scroll/footer контейнеров, использует safe `start`/`end`/viewport-aware placement у левого, правого и нижнего края окна и не выходит за пределы viewport.
- UI scrollbar smoke должен проверять, что desktop и browser shell используют единый глобальный scrollbar contract эталонной подпанели `Tracked apps`: `8px` ширина/высота, `thin` Firefox-style, тёмный track, серый thumb, одинаковый hover и `3px` radius для `Tracked apps`, `Ignored addresses`, `Monitoring` table, language dropdown, path-field и main content scroll.
- UI startup tests должны проверять, что cold-start snapshot не делает сетевой запрос и не блокирует первый paint окна.
- UI/cloud credential tests должны проверять, что Google OAuth flow не сохраняет Google access token, OAuth client secret, пользовательские пароли или provider credentials в SQLite/логах, а Worker хранит Google subject/email только как HMAC-значения через `NETSTITCH_IDENTITY_PEPPER`. После успешного Google OAuth local session/client state и display-only Google name/email сохраняются только как Windows DPAPI-защищённые blobs, а кнопка `Выход` должна подтверждать logout и удаление local session/client state, DPAPI-защищённых Google name/email blobs, безопасных account metadata и obsolete login/password/stay-signed-in keys. Cloud overlay tests должны проверять две равные по высоте панели download/upload, service-status в header обеих панелей, лимиты и compact progress bar в footer соответствующих панелей, отсутствие progress bar в общем footer приложения, отсутствие ручных кнопок `Обновить`/`Закрыть`, автоrefresh каждые 10 секунд только пока overlay открыт, общий refresh-deadline `9.5s` из 10-секундного интервала и защиту от применения устаревшего refresh-result поверх свежего sign-in/sign-out. Cloud helper tests должны проверять одноразовость OAuth `state`/PKCE, TTL и used-at marker, отдельный limit OAuth start `5 за 15 минут`, server-issued SVG captcha verification (`23456789`, длина `6`, TTL `300s`, минимум `5s`, max `3` попытки, pool `6`, tile render `10 x 3` через JS), наличие icon-only captcha refresh action, голубую кнопку отправки капчи, 3x zoom overlay с blur-backdrop, один компактный столбец OAuth captcha layout с полем ввода шириной капчи, отсутствие `accounts.google.com`/Google OAuth URL в HTML до капчи, отказ прямого POST без капчи/browser-verification и server-generated Google OAuth redirect `302 Location` только после успешной проверки капчи и browser-verification, наличие state-bound SHA-256 proof-of-work, `seeded-memory-walk-v1`, Worker/canvas/WebGL/timing/interaction signals и pointer percent risk fields, rate-limit `3 за 1 час`, session/client key binding, передачу текущей UI-локали в OAuth-state и JWT upload integrity (`jti`, `body_sha256`, TTL).
- Cloud upload tests должны проверять два trust-path: verified observations требуют совпадающий локальный stable app identity key, где key строится из валидного Authenticode leaf SPKI при наличии и стабильных VersionInfo `CompanyName`/`ProductName` без версии/пути/имени exe, а импортированные/неподтверждённые observations отправляются как `CloudImportUntrusted` с исходной imported signature. Worker не использует предварительный список издателей: `app_catalog` пополняется из authenticated upload payload, а запрет выполняется только для явно `blocked` app ids. Live Worker smoke после D1 schema change должен проходить после применения миграций; `publisher_key` обязан оставаться частью физической uniqueness/provenance observations, но public/private cloud catalog/download должны агрегировать строки по общему Monitoring/CSV ключу `app_id + IP + port + protocol`; приватный/author-scoped срез и dropdown `Все/Общие/Приватные` проверяются отдельно. UI regression должен проверять, что cloud staging показывает колонку `Прив.`/`Private` со значениями `true`/`false` только внутри cloud import/export boundary, что `Добавить в мониторинг` и `Экспорт CSV` требуют явного выбора строк, что import result отображает requested/imported/skipped counts без лимита 500, что progress bar использует сегменты по 500 строк, а `MonitoringCsvImportRowDto` и CSV export не получают privacy marker.
- Live Cloudflare smoke для текущего production Worker выполняется через `tests\cloud_auth_smoke.ps1 -BaseUrl https://netstitch-sync.warfactory.workers.dev` или через `NETSTITCH__CLOUD_BASE_URL`; если Windows TLS/Schannel мешает `Invoke-WebRequest`, допускается ручная WSL/curl-проверка `/v1/health`, `/v1/auth/google/start`, `/v1/auth/session/poll`, `/v1/client/quota`, `/v1/apps` и anonymous rejection `/v1/users/me/apps`.
- UI layout smoke должен проверять глобальный window layout: native titlebar показывает `NetStitch ver. <version>`, внутренний app header не выводит `NetStitch MVP`/subtitle, имеет уменьшенную фиксированную высоту и содержит фильтр наблюдений, поиск, `toggle-monitoring`, `confirm-filtered`, `export-confirmed` и switch `Web localhost`; footer имеет фиксированную высоту, header/footer постоянно закреплены на месте, использует единую project palette и stable UI entity-контейнеры: `Apps: enabled/total`, watcher, `Tool`, `Web server`, `DNS`, затем `footer-message-panel` с последним сообщением из SQLite `system_events`, copy-history кнопкой `20x20` для последних 100 строк и tooltip последних 6 строк без переноса. Header панели `Monitoring` должен показывать switch `Публичные` со стилем switch-ов главного header и сохранением состояния в SQLite `app_settings` с ключом `ui.monitoring.public_ip`, footer панели `Monitoring` должен показывать `Строк`/`Отображено`/`Выбрано`, а таблица `Monitoring` не должна иметь отдельную колонку публичности IP; `Lines`/`Строки` в общем footer приложения не выводятся. Message history берётся из `system_events`: footer показывает последние 10 сообщений, copy-history копирует последние 100, startup пишет build/current/app/watcher/tool/web/DNS и connector/module diagnostics, severity сохраняет цвета, одинаковые подряд события схлопываются через `repeat_count`, а таблица ротируется до 9999 строк. `Integration note: No export yet` и `The UI will retry automatically` в footer не выводятся; web server on/off, fallback на localhost, monitoring start/stop, confirm/export, copy actions, watcher connected/disconnected events и connector load summary тоже должны логироваться.
