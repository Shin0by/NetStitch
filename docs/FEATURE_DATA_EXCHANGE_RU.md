# Импорт и экспорт данных

NetStitch поддерживает перенос наблюдений между рабочими средами через CSV и облачное хранилище. Оба режима используют один принцип схлопывания строк: одинаковые наблюдения объединяются, а новые endpoint-строки добавляются к текущему набору.

## CSV

CSV подходит для ручного переноса данных:

- экспорт сохраняет выбранные строки мониторинга;
- импорт добавляет строки в текущий мониторинг без очистки существующих данных;
- совпадающие IP, порт и протокол объединяются;
- домены переносятся как часть наблюдения, если они уже есть в строках;
- идентификаторы приложения и подпись происхождения сохраняются, если они есть в файле.

## Домены и диапазоны при экспорте

Домены используются как дополнительное доказательство назначения строки. Если домен уже найден мониторингом или пришёл из доверенного импорта, он может быть перенесён в CSV и использован в дальнейшей обработке.

Диапазоны помогают работать не только с отдельными IP, но и с адресными блоками. Когда для IP известен диапазон, NetStitch может использовать эти сведения при подготовке данных к экспорту, чтобы пользователь мог работать с более устойчивым набором сетевых назначений.

## Где доступно

- CSV: кнопки верхней панели `Импорт CSV` и `Экспорт выбранных в CSV`.
- Облачная загрузка: кнопка `Импорт Облако` -> окно `Облако: загрузка данных`.
- Облачная выгрузка: кнопка `Экспорт Облако` -> окно `Облако: выгрузка данных`.
- Добавление облачных строк: `Облако: загрузка данных` -> выбрать строки -> `Добавить в мониторинг`.
- Экспорт облачных строк: `Облако: загрузка данных` -> выбрать строки -> `Экспорт CSV`.
- Локальные данные portable-сборки: `storage/`; CSV-файл сохраняется или выбирается в пути, указанном пользователем.

## Облачное хранение

Облачный обмен нужен, когда набор наблюдений должен быть доступен с другой машины или другому пользователю NetStitch.

- Публикация отправляет подтверждённые строки выбранного приложения.
- Загрузка показывает найденные приложения и таблицу строк перед добавлением в мониторинг.
- Строки из облака можно добавить в мониторинг или экспортировать в CSV только после явного выбора строк в staging-таблице.
- Счётчик результата показывает, сколько строк было выбрано, сколько добавлено и сколько пропущено; прогресс загрузки/выгрузки идёт шагами по 500 строк.
- Домены и данные строк сохраняются в том же логическом наборе, что и локальный мониторинг.
- Веб-интерфейс использует тот же локальный runtime NetStitch, что и desktop-версия.

## Приватный режим

При публикации можно выбрать обычную или приватную выгрузку.

- Обычные строки видны в общем наборе.
- Приватные строки доступны владельцу аккаунта и могут существовать отдельно от таких же обычных строк в облаке.
- При загрузке фильтр `Private` позволяет выбрать `Все`, `Общие` или `Приватные`.
- Признак приватности показывается только в облачной таблице импорта колонкой `Прив.`: `true` для приватных строк и `false` для общих.
- После добавления в мониторинг или экспорта в CSV признак приватности не переносится.

Такой контур позволяет хранить общий набор данных и личные публикации рядом, не смешивая приватность с локальной таблицей мониторинга.
## Теги в CSV и облаке

Локальный CSV заканчивается столбцом `tags`: несколько локальных тегов пользователя разделяются `;`. Теги, использованные только для фильтрации скачанных cloud-строк, локально не сохраняются. Поэтому CSV из cloud staging содержит тот же последний столбец, но оставляет его пустым.

Теги назначаются приложениям в панели `Отслеживаемые приложения` и автоматически накапливаются у наблюдаемых строк. Квадратная SVG-кнопка `T` имеет размер соседней кнопки `X`: без тега она тёмная, с тегом голубая как активный switch; tooltip поясняет разделение данных приложения на регионы или группы. Modal не закрывается кликом по затемнённой области, после назначения/снятия тега и закрывается только кнопкой `Закрыть`. Менеджер без дублей объединяет текущие теги приложений, теги локальных строк и облачный каталог. Предзаполненный текущий тег не фильтрует варианты; поиск начинается после ручного ввода. После применения фильтр очищается, весь список возвращается, а текущий тег подсвечивается. Локальная история учитывает только строки, доступные контуру `Мониторинг`: строки, скрытые правилами `Игнорируемые адреса`, не сохраняют вариант тега после снятия его со всех приложений. Обычные поисковые и header-фильтры на историю не влияют. Теги автора идут первыми и выделены синим, собственные теги, уже присутствующие в облаке, — зелёным, остальные облачные — стандартным цветом. Для любого собственного тега доступно удаление только на этом устройстве либо на устройстве и в облаке; удаляются связи тега, но не строки мониторинга. В `Мониторинге` колонка `Тег` находится сразу после приложения и показывает примерно восемь символов в однострочном прокручиваемом поле.

Cloud export не создаёт и не назначает теги. Общая кнопка `Очистить теги` очищает все локальные теги выбранных в `Мониторинге` строк и не удаляет уже опубликованные cloud-связи. Верхняя подпанель export содержит только элементы авторизации и подпись автора; `Приватная выгрузка` и `Очистить теги` расположены одной строкой во вложенной подпанели `Публикации автора` над таблицей. Строки одного приложения группируются отдельно по точному набору локальных тегов. Крайняя правая компактная колонка `Тег` рассчитана только на заголовок и кнопку, а длинное содержимое прокручивается внутри; `X` у конкретного тега удаляет только его у локальных observations этой группы. Cloud import поддерживает отдельный substring-фильтр тега между автором и приватностью.
